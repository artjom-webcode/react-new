# Prop Drilling vs Composition

Учимся не прокидывать state через компоненты-посредники, а собирать нужные части прямо там, где стейт живёт.

```jsx
function App() {
  const [selected, setSelected] = useState(null);

  return (
    <div>
      <Cart>
        <Header title="lite подписка" />
        <Text text="25 euro" />
        <button onClick={() => setSelected("lite")}>Купить</button>
      </Cart>

      <Cart>
        <Header title="premium подписка" />
        <Text text="100 euro" />
        <button onClick={() => setSelected("premium")}>Купить</button>
      </Cart>

      {selected && <p>Выбрано: {selected}</p>}
    </div>
  );
}

function Cart({ children }) {
  return <div>{children}</div>;
}

function Header({ title }) {
  return <h2>{title}</h2>;
}

function Text({ text }) {
  return <p>{text}</p>;
}
```

Состояние `selected` живёт в `App` — это единственное место, где оно создаётся через `useState`. Кнопка `<button onClick={...}>`, которая это состояние меняет, физически находится внутри `Cart`, но при этом код кнопки написан прямо в `App`, а не внутри компонента `Cart`. Это и есть суть composition: `Cart` просто отображает `children`, а сам JSX с кнопкой и обработчиком `onClick` собирается снаружи, в родителе, и туда же "вкладывается".

Если бы вместо composition использовался обычный prop drilling, пришлось бы делать иначе: `Cart` принимал бы проп типа `onBuy` или `planName`, передавал бы его дальше в какую-то внутреннюю кнопку, и `Cart` знал бы о логике покупки, хотя по смыслу он должен быть просто нейтральной "рамкой" для контента. Такой `Cart` было бы сложнее переиспользовать — он был бы завязан на конкретную бизнес-логику подписок, а не был бы универсальным контейнером.

Здесь этой проблемы нет: `Cart` как компонент вообще не в курсе, что где-то внутри него есть кнопка, меняющая `selected`. Он просто рендерит то, что ему передали. `Header` и `Text` тоже ничего не знают про state — они получают только свои узкие пропсы `title` и `text` и ни для чего больше не нужны.

Строка `{selected && <p>Выбрано: {selected}</p>}` — условный рендеринг: если `selected` ещё `null` (ничего не выбрано), выражение после `&&` не вычисляется и ничего не рендерится. Как только `selected` становится строкой ("lite" или "premium"), под карточками появляется текст с выбором.

Итог: prop drilling — это когда проп идёт через компоненты, которым он не нужен, просто транзитом вглубь дерева. Composition решает это тем, что нужный код (обработчики, конкретные значения) пишется прямо там, где требуется, а компоненты-обёртки вроде `Cart` остаются полностью нейтральными и переиспользуемыми, принимая всё через `children`.
